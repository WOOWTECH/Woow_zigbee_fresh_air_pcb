# V3.3 驗證報告：NFC 設定介面

V3.3 在 V3.2（4 路 DI）的基礎上加了 NFC：手機 App 貼近板子，就能讀寫 DI／DO 模式、點動時間、遙控器清單等進階設定。Apple Home／Google Home 只能做開關，這些設定改由 NFC 處理，不需要 Wi-Fi 熱點，也不會讓 Matter 斷線。

- **NFC 晶片**：U6 ST25DV04KC（C3304276）。手機端走 ISO 15693（NFC Type 5），iOS Core NFC 和 Android 都支援；ESP32 經 I2C 讀同一份資料。
- **天線**：L5，板上印刷線圈（不另外買天線），14.9×14.6mm、8 圈。
- **J5 改到左側板邊**：DI 電線從左側出，左上角留給線圈。左半段上緣從 y=93.08 提高到 107.2mm。

PCB 一樣以 V3.1 為起點，用同一支腳本重建：`WO_VER=3.3 python3 scripts/upgrade_v32_pcb.py`。不跑 Freerouting，市電區、繼電器區、433 匹配區的佈線都不動。

|---|---|---|
| 1 | ERC | 0 錯誤、0 警告 |
| 2 | DRC（含市電安規）與原理圖一致性 | 錯誤 0、未連線 0、不一致 0；警告只有絲印類 |

## 1. 電路

```text
          L5 印刷線圈 1.27µH                     U6 ST25DV04KC（SO-8）
   AC0 ─┬─────(((((((((((─────┬─ AC1        2 AC0      VCC 8 ── +3V3 ─ C23 100nF
        ├── C22 75pF C0G ─────┤             3 AC1      SDA 5 ── R24 10k ↑ ── IO20（U1 第 18 腳）
        └── C24（空位，微調）─┘             4 VSS      SCL 6 ── R25 10k ↑ ── IO19（U1 第 17 腳）
                                             1 V_EH（不用）  GPO 7（不接）
```

- **ST25DV04KC 腳位**（ST 規格書 Figure 2，SO8N）：1 V_EH、2 AC0、3 AC1、4 VSS、5 SDA、6 SCL、7 GPO（開汲極）、8 VCC。
- **記憶體**：使用者 EEPROM 4Kbit（512 bytes），另有 256 bytes 的 mailbox。手機和 ESP32 之間的即時一問一答走 mailbox。
- **GPO 不接**：韌體每 50ms 用 I2C 讀一次 IT_STS_Dyn 暫存器（RF 場、mailbox 狀態）。少一條長線；50ms 的反應時間對設定介面足夠。
- **V_EH 不接**：能量擷取輸出預設關閉。
- **I2C**：上拉 10kΩ（BOM 已有的基礎料）。ST25DV 的 I2C 位址是 0x53（使用者記憶體）／0x57（系統設定）。

### 線圈與調諧（`scripts/nfc_coil.py`）

ST25DV 內建調諧電容 28.5pF。要諧振在 13.56MHz，線圈需要 4.83µH，但板上只有 15mm 見方，8 圈只做得到 1.27µH，所以並聯 C22 補足電容。這是小型 NFC 天線的標準做法。

| 外加電容 | 諧振頻率 |
|---|---|
| 68pF | 14.33MHz |
| **75pF（C22，C1681）** | **13.84MHz** |
| 82pF | 13.40MHz |

- **故意調在 13.56MHz 以上一點**：裝進塑膠外殼、手機靠近之後，諧振會往下掉幾百 kHz。
- **C24 留空位不焊**：打樣後用 VNA（或手機感應距離）實測，必要時加幾 pF 微調。
- **電感計算**：讀封裝裡的實際銅箔線段，用部分電感法計算（直線段自感＋平行段互感數值積分）。程式和矩形單匝公式解相比，22×16、40×25、10×10mm 三種尺寸差都在 0.1–0.2% 以內。
- **線圈封裝**（`WOOW:NFC_Coil_14.9x14.6mm_8T`）：
  - 線寬／間距 0.2／0.2mm，畫在正面；最內圈端點經 THT 焊盤，從背面拉到線圈外。
  - net tie（"1, 2"）：讓線圈銅箔合法連接兩個焊盤（電感在直流是短路）。
  - 禁布區（線圈外擴 0.5mm）上下兩層禁止鋪銅和過孔。走線限制放寬，是為了放線圈自己的背面跨線；別的網路由佈線器擋在外面。
  - 背面跨線由 PCB 腳本畫成真正的走線。封裝圖形不算連接，如果把跨線畫在封裝裡，內外兩個「2」號焊盤會被判成未連線。
- **75pF 的庫存**：JLC 約 3000 顆，打樣和小量沒問題；量產時可改用 68pF（C1680，庫存近 10 萬）再加 C24 微調。

## 2. ESP32 腳位重新分配

V3.3 的上排有 6 條線要進 ESP32：DI_1–4 加上 I2C 兩條。如果照 V3.2 的接法，DI 長線和 I2C 長線會在 U3（433 接收晶片）底下互相交叉，佈線器找不到路。改成照左右順序一對一接，彼此就不交叉：

| 起點（左→右） | DI_1（C18） | DI_2（C19） | DI_3（C20） | DI_4（C21） | SDA（R24） | SCL（R25） |
|---|---|---|---|---|---|---|
| U1 腳 | 26 | 23 | 20 | 19 | 18 | 17 |
| GPIO | IO3 | IO15 | IO22 | IO21 | IO20 | IO19 |

- **IO15 是 strapping 腳**：只有燒了 `EFUSE_JTAG_SEL_ENABLE` 才會在開機時讀它（用來選 JTAG 來源），出廠預設不讀。所以 DI_2 在開機時被接點拉低也不影響開機。
- 其餘 strapping 腳（GPIO4、5、8、9）都沒有用到。
- **韌體 `board.h` 要改成 V3.3 的腳位**，會在 NFC 韌體 PR 一起改。V3.2 的腳位（DI 接 IO22–IO19）只適用於 V3.2 板。

## 3. 佈局

```text
   y=75.9 ┌───────────────────────┐
          │ J5 ▶│  L5 NFC 線圈     │   ← J5 開口朝左；由下往上 +12V、IN1–4、COM、GND
  (左側   │ 7P  │  14.9×14.6mm     │
   出線)  │     └──────────────────┤
          │       C22 C24   U6     │
   y=100  │ P2   B1      U5        ├─────────┐ ← P1（AC IN）前方維持原板緣
          │  ESP32 …               │  P1 F1 RV1 …
```

- **J5**：直立貼左側板邊，開口朝左。這個封裝開口朝左時 1 腳一定在下面，所以由下往上依序是 +12V、IN1–IN4、COM、GND；背面絲印印在焊盤右邊。
- **R15–R18、R23**：放在背面、J5 本體底下（板邊和焊盤之間），分兩欄交錯，各自對齊所接的腳。R23 放在左欄最上面，讓下方 y≈100 的窄帶留給 DI 線出去接 U5。
- **L5**：x 110.5–125.4、y 76.4–91.0（KiCad 座標）。距 J5 焊盤 2mm、距板邊 0.5mm；距最近的市電銅箔（P1）超過 15mm。
- **U6、C22、C24**：正面，放在線圈正下方；AC0／AC1 在 U6 左側，靠近線圈焊盤。C23（去耦）、R24／R25（上拉）放在 U6 正背面。
- **佈線順序**：依序佈線時，結果和順序有關。以下是試出來的順序，原因都寫在腳本註解裡：
  1. U5 周邊；
  2. NFC 短線；
  3. I2C 長線（先佈外側的 SCL）；
  4. +12V（R23 在左上角，從 U2 拉過來）；
  5. DI 長線，自動試所有排列；
  6. 最後是 +3V3，一路接 U6、C23、上拉電阻，再接回 P2 和 U3。

## 4. 這次修掉的佈線器問題（`mains_router.py`）

- **禁布區沒有算線寬**：只塗禁布區多邊形的話，走線中心可以貼著邊緣，線寬就吃進禁布區 0.2mm。現在多邊形外圍再擴「半線寬＋0.05mm」。
- **只認禁止走線的禁布區**：現在禁止走線**或**禁止鋪銅的禁布區都算障礙。
- **只認矩形板框**：現在讀真實板框（L 形），板外再往內擴「板邊間距＋半線寬」。原本有一顆過孔離 L 形轉角太近。
- **KiCad 10 API 名稱**：`GetDoNotAllowZoneFills`（不是 CopperPour）、`GetBoardPolygonOutlines(ps, False)`。
- **`add_stitching.py --prune`**：同時移除 DRC 判為懸空的 GND 過孔。新走線把背面鋪銅切開後，舊的縫合過孔可能只剩一層接得到。
- **殘線清理**：範圍加上 P2 第 1 腳附近。V3.3 擺件後那裡留下一段 1.8mm 的 +3V3 殘線。

以上都只是讓佈線器「更保守」。V3.2 用新程式重建後 DRC 依然乾淨（§5）。

## 6. BOM 與成本

- **新增**：U6 ST25DV04KC（擴展料，$0.94／1 片、$0.59／100 片）、C22 75pF C0G（擴展料）。
- **沿用 BOM 已有的料**：C23 100nF、R24／R25 10k。
- **不上件**：L5 是純銅箔；C24 是微調空位。
- **合計**：30 種、64 顆。比 V3.2 多 2 種擴展料，上料費多約 $3–6（每張訂單一次）。

## 7. 待辦與限制

- **韌體（另開 PR）**：
  - ST25DV I2C 驅動、設定資料格式與 mailbox 指令（給 App 開發用的規格文件）；
  - `board.h` 改成 V3.3 腳位；
  - 電腦端測試工具（USB NFC 讀卡機）。
- **打樣後實測**：
  - 諧振頻率（VNA 量 AC0–AC1，或比較手機在不同距離能不能讀到），必要時用 C24 微調；
  - iPhone／Android 在外殼外的感應距離（預估 1–2cm）；
  - 線圈靠近 ESP32 天線（約 35mm）時，會不會影響 Zigbee／Thread。
- **外殼**：
  - 板子變成 L 形，左半段高 107.2mm、右半段維持 83.08mm；
  - 線圈那一面要是塑膠，而且要貼近外殼表面，並在外殼上標 NFC 感應位置；
  - DI 電線改從左側出線。
